## 已复核的公开结果

四个公开JSONL文件共约11.5MB，在服务器`results/20261028-abstention-artifact-audit-v1`，全部Git blob与SHA256通过。两份实际KV输出各463行、来自相同100个源问题的不同保留率；id/比例/gold/n_kept逐行配对相同。不是463个独立问题。另有400条作者LLM-judge标签核查及其1D文本mask输入。

| 按作者保存标签/分类重算 | 基础模型 | 混合训练适配器 |
| --- | ---: | ---: |
| correct / 463 | 86 | 380 |
| Abstain标签 / 463 | 366 | 366 |
| Confident标签 / 463 | 97 | 97 |
| Confident标签中回答正确 / 97 | 4 | 24 |
| Confident标签中过度拒答 / 97 | 36 | 48 |
| Confident标签中错误回答 / 97 | 57 | 25 |

本池的always-abstain规则按作者标签可得366/463=79.05%，适配器380/463=82.07%，多14行（3.02个百分点）。这是对类比例敏感性的诊断参照；既不代表always-abstain有正常效用，也不推翻适配器相对基础模型的显著行为变化。Confident/Abstain是作者span代理标签，不能直接当真实语义可答性。不同保留率必须分别报告，不能只看这个混合总分。

源码拒答标记包含宽泛上下文短语：基础模型23条出现，19条仅命中这两种宽泛标记，其中作者分类10 correct、9 overcautious；适配器0条。若只重判这19条，任意总分变化至多19/463=4.10个百分点，无法解释两模型294条correct差距。人工单读也看到真正表达缺信息、肯定回答及自相矛盾的混合情况；因此不把全部标记自动记为评分错误，更不将作者结果归零。没有重写论文gold，也没有将本会话语义判读当多标注者认证。

400条标签核查与作者披露一致：Confident→YES/NO/PARTIAL为123/55/22；Abstain→NO/YES/PARTIAL为160/14/26。剔除48条PARTIAL后352条，原始一致率0.80398、κ=0.60894。judge是作者LLM评估而非我们的人工真值，输入为1D文本mask，不是分层分头KV内部语义状态。这些误差已为作者披露，不能作为本项目首次发现。

首次分析v1失败原因是我们把已保留三位小数的span比例当未舍入数值核对；56条受影响。v2按公开精度比较，400条mask长度/保留数/span比例及全部输入哈希通过。原mask未改，失败与源码副本保留；这不是作者原始mask不一致。

## 对研究候选的影响

- “删证据后拒答”已被Compression-Aware Abstention覆盖；训练标签的冗余证据和语义充分性限制也已明确讨论。
- [Sufficient Context](https://arxiv.org/html/2411.06037v3)已研究充分性判断、选择性回答和训练；不能仅换到KV就声称提出了通用充分性概念。
- [Does Accuracy Equal Evidence?，EMNLP2026](https://aclanthology.org/2026.findings-emnlp.350/)已研究压缩后答案与证据支持分离并使用固定轨迹/扰动验证；泛“答案还在、证据链丢了”不是空白。
- [KVDiagnosis](https://arxiv.org/html/2608.09412v1)已做配对失败、分层分头coverage、漂移和受控干预；保留位置、内在信息与可访问性须分清。
- [Error Certificates](https://arxiv.org/html/2607.21475v1)已有随机化误差归因和重算调度，同时报告预测与预算升级的负结果；不能未经比较提出通用“置信度检测失败后回退”。其注意力误差结论不自动是实际任务安全保证。

所以候选C的**当前宽泛表述不进入模型矩阵或训练**。这没有证明所有更专门的充分性估计/恢复方法都不可做；要继续，需说明部署可见信号、超过简单输出置信度/规则保护/检索的差异，以及真实KV下正常回答与拒答双向效用。

## 转向审查的具体问题

当前只读审查固定预算下安全检测模型自身的历史KV。已有[TRACE](https://arxiv.org/html/2606.00611v1)、[Defensive M2S](https://arxiv.org/html/2601.00454v1)、[StepGuard](https://arxiv.org/html/2608.24777v1)、[StepSafe](https://arxiv.org/html/2610.20960v1)覆盖安全轨迹证据聚合、文本/潜在压缩、动作级判断和及时干预，因此不能把“更早检测风险”或“压缩guard”直接当新意。

拟核查的窄问题：在**历史KV不可逆删除、未来候选动作未知、固定实际缓存预算**时，任务训练过的guard会否因丢失历史授权/条件证据而错误放行；相同历史的安全与不安全候选动作应配对，并与简单完整指令保护、最近窗口、整步保留和历史证据检索比较。此处仍只是研究问题，尚无方法贡献或真实模型结果。

Qwen3GuardTest的来源预检已给出一个明确no-go：所有记录只有user/assistant两条消息，thinking_loc首危险句最晚322token、512之后0条，response_loc最晚120token；长响应不等于晚发生的首次风险。不能加填充或把早已危险的后续响应当作“长历史首次预警延迟”。下一步只审StepGuard/StepSafe原始输入契约、逐步标签和数据隔离，再决定是否值得冻结一次独立能力关卡。
