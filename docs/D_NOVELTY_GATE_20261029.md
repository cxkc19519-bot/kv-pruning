## 2. 当前容易重复的三个主张

1. **“保留安全相关历史，避免动作漏检”**：MAGE已经实现这一架构，TRACE已研究风险证据聚合。
2. **“不知道未来动作，所以按步骤/依赖保留”**：MAGE的记忆更新、LRE的query-blind选择、StepKV/CommitKV分别覆盖相应部分。不能仅靠“未来未知”区分。
3. **“实际KV预算比文本摘要更严格”**：这是需要明确的系统设定，尚不是方法或收益证据；同样应该比较文本提取/摘要后重新编码的实现，计入其成本。

此前“只准生成草稿，后来准备发送”的示例不足以证明复杂记忆方法有必要：完整保留用户指令配合动作检查，就可能解决该例。这里是可检查的简单解释，不是测得基线正确率。以后不能以这种例子单独证明复杂依赖机制。

## 3. 必须先固定的资源契约

尚未注册实验数值或上限，以下是后续设计要求，不是已启用实验。

| 项目 | 要记录什么 | 常见不公平比较 |
| --- | --- | --- |
| 持久GPU状态 | 每层/head实际K/V字节，索引、辅助状态、额外常驻模型 | 只报保留token比例或忽略辅助模型。 |
| 峰值 | 完整prefill临时KV、克隆/工作区、重编码、分数提取 | 声称固定内存，却保留未计入的完整参考cache供恢复。 |
| 外部存储 | CPU/磁盘原文、检索索引、来源信息 | 使用原文回读但称所有历史已删除；或只为新方法禁止检索。 |
| 每步读取/计算 | 记忆更新与judge全部输入/输出、检索编码、重编码；一次索引构建单列 | 将MAGE记忆更新视为免费，或把检索编码成本藏在预处理。 |
| 时延 | 检索、prefill/更新、KV改动和判定的端到端时间 | 缓存驻留字节相同就声称计算或时延相同。 |
| 可用信息 | 历史更新时是否知道当前待审动作，宿主提供哪些来源/权限元数据 | query-blind新方法与偷看未来动作的基线混比，或相反。 |

需要区分两种部署：

- **允许保存并回读原文。** 应比较当前动作驱动的BM25/词法匹配、相邻整步窗口、原文提取后重编码以及有效fallback，回读和计算统一记账。不能为了制造新方法收益而取消普通检索。
- **确实不能回读原文。** 原因必须来自实际应用约束，而非临时禁用强基线。各方案都在相同可用信息与存储限制下运行；MAGE式流式文本记忆、LRE式提取和真实KV方法均可比较，写入/更新成本照计。

两个设定不同；不把一种的结果外推到另一种，也不把模型自身可见的信息约束写成系统安全保证。字符、原生token、latent槽数和KV字节不能混作同一预算。

## 4. 强基线与进入实验的门槛

| 强基线 | 应回答的问题 |
| --- | --- |
| Full、NoHistory、固定窗口、等预算随机 | 原任务是否会做、是否依赖历史；NoHistory改变文本/位置，不是KV效应。 |
| 完整用户指令保护＋最近步骤 | 简单授权示例是否已经被解决；保护成本包含在总预算。 |
| 当前动作检索＋相邻完整步骤＋重编码 | 是否只需要在需要时找回少量原文；匹配全序列化长度和读取/计算口径。 |
| 原文整步提取、LRE式廉价相关性 | 复杂训练/latent机制是否有超出低成本选择的价值；若改到KV索引保留，标为适配版本。 |
| MAGE式安全文本记忆 | 相同guard任务下维护独立安全记忆是否已经足够；训练模型与prompt-only替代不能混称作者复现。 |
| StepKV/CommitKV式真实KV方法 | 超过一般步骤/生命周期保留，而不是只超过朴素token top-k。 |
| TRACE | 对照证据聚合能力；保留全部原轨迹的部署资源必须照计，不强塞进不满足的硬上限。 |

进入新实验前必须同时具备：明确且真实的资源契约；原输入可判定的safe/unsafe标签；独立于输出筛选的开发集合；能够表述为什么上述强基线可能不足的具体机制和相应控制；新的工程正确性设计。当前这些条件尚未全部满足。

尤其不能预先声称“简单方法解决不了”：本次只有文献判断，没有跑过这些基线。后续如比较，应分别报告unsafe误放行、safe误拦截、全部样本及Full四转移，按独立交互分组，不能靠一概拒绝换安全分。
