## 问题形式化与已有方法的对应

独立单位为前缀世界及事先规定的查询包：

\[
 Z_i=(P_i,Q_{i1},\ldots,Q_{iM}),\quad Z_i\overset{iid}{\sim}\mathcal D.
\]

查询包内允许相关，不同前缀世界独立；查询来自固定采样规则，不包括任意自适应攻击保证。已冻结策略\(\pi_\lambda\)在查询未知时从部署可见的前缀特征决定预算/索引。不能利用CAL或TEST答案重新训练策略，也不能把各query当独立前缀。

对预定类别\(g\)，可以定义每前缀一个二元损失：

\[
 L^S_g(Z_i;\lambda)=\mathbf 1\{\text{该类别查询包至少一次违反约束}\},
 \quad L^U_g(Z_i;\lambda)=\mathbf 1\{\text{正常效用损失超过预定容忍量}\}.
\]

这是固定大小查询包的风险，不是对所有可能query的最坏情况保证。允许请求错误、过度拒答、禁止内容披露应定义独立损失，不能用总分抵消。若并非每个前缀都含每类query，需另行明确条件分布与有效样本数，不能把缺失类别记为零风险。

| 想提出的部分 | 已有方法如何直接覆盖 | 判断 |
| --- | --- | --- |
| 安全与效用同时受限 | [LTT §2.4 Proposition 6](https://arxiv.org/html/2110.01052v5)：多个风险的联合检验 | 不是新统计方法 |
| 不同类型分别达标 | 每类定义一个风险，要求全部分量达标；组内相关可保留为一个采样单位 | 合法测量设计，不自动是研究贡献 |
| 一个前缀服务多个query | 将固定查询包整体作为随机单位后仍是普通有界损失；[KVzip](https://arxiv.org/abs/2505.23416v2)已有query-agnostic复用 | 不是新机制或新保证 |
| 按前缀特征分配不同预算 | 候选\(\pi_\lambda\)本身可以是输入自适应策略；[Risk-Controlled §3.3](https://arxiv.org/html/2609.27981v1)已支持此类策略校准 | 不能仅用“自适应”区分 |
| 在多约束下省内存/时间 | [Pareto Testing §4–5](https://arxiv.org/html/2210.07913v1)：在独立数据上找候选Pareto前沿，再检验风险、优化自由成本 | 不是新的优化框架 |
| 用熵/困惑度预测压缩风险 | [CompilerKV §4.4](https://arxiv.org/html/2602.08686v1)已有前缀相关风险门控 | 换成安全标签仍需新的机制与证据 |

这些对应说明当前方案可由已有方法直接组成一个合法基线，不是证明任何具体工程实现都会可靠，也不排除未来出现有实质价值的专用问题。当前不应先给上述组合命名，再靠实验寻找贡献。

## 联合检验不必逐风险分摊置信预算

对一个固定策略\(j\)，若每个分量的\(p_{j,g}\)对“该风险不达标”原假设有效，联合原假设是“至少一个风险不达标”，则

\[
 p_j=\max_g p_{j,g}
\]

是有效p值。若分量\(g_*\)不达标，事件\(\{p_j\le\delta\}\)蕴含\(\{p_{j,g_*}\le\delta\}\)，所以错误认证概率至多\(\delta\)。分量之间不要求独立。这是LTT已有的intersection-union结论；多策略选择仍需固定顺序或其他合适的FWER控制，不能查看一堆结果后任取最小p值。

因此，上轮报告的“四组Bonferroni每组86个零失败样本”是一个保守方案，不是不可降低的样本下界。对**单个固定策略、要求全部分量同时通过的联合契约**，在各分量都有iid单位且零失败的理想条件下，每分量59个即可使\(0.95^{59}\le0.05\)。这不是59个总query、不是对任意数据设计的保证，也不能直接用于本项目少量开发数据。

## CPU精确检查与反例

源码[scripts/audit_prefix_risk_design.py](../scripts/audit_prefix_risk_design.py)使用标准库Fraction精确枚举，不加载任何模型。服务器运行`results/20261028-prefix-risk-design-audit-v1`，882个联合原假设检查、22925个多项分布结果枚举全部通过。它检查有限例子的概率计算，不代替一般数学证明，也不能自动检测新颖性；no-go来自上文文献归约判断。

| 数学例子 | 计算结果 | 含义 |
| --- | --- | --- |
| 8独立prefix，每prefix8个完全相关query，全部零失败 | 错把64query当iid时p=0.03752；正确prefix单位p=0.66342 | 可制造错误“95%认证”；这是构造反例，不是模型实测 |
| 16个独立候选都处于5%风险边界，各用60个独立样本且零失败就过 | 单候选错误通过概率0.04607；任一通过就选时0.52982 | 后验挑选会严重膨胀错误认证概率；这里候选独立仅为构造示例 |
| 预定顺序p值0.01、0.2、0.001 | 只接受第一个，第二个失败后停止 | 风险可非单调，不能以之后更好为由静默跳过停止规则 |
| Full绝对失守率20%，相对自身新增损坏0 | 相对退化契约通过，绝对安全契约不通过 | Full回退不等于绝对安全，需要拒绝部署或独立有效的外部控制 |

两个已知需求分别0.25/0.75的toy前缀，通过普通有限枚举就能把均匀0.75改成平均0.5。该算术例子没有真实模型压缩收益，只说明“不同上下文用不同预算”不能仅凭一个节省数字成为新算法。

## 同窗口继续审查的更窄问题

本轮继续补查发现一个可具体定位的**未解决现象线索**：[Compression-Aware Abstention §限制](https://arxiv.org/html/2608.29934v1)明确指出，高保留率下只丢关键证据的少量例子仍会幻觉；其短答案片段标签也未必表示完整语义证据充分。该论文已训练拒答适配器、做固定长度及针对性删除控制，并评估实际压缩KV，所以不能把“证据丢了就拒答”或“使用桥接子答案”当作新题。

接下来的离线审查问题是：**能否在实际分层/分头的压缩KV中，识别“答案实体还在、关系或条件证据不完整”的情形，并避免无依据回答与一概拒答？** 先核查其标签/源码、KVDiagnosis及一般上下文充分性研究，再决定是否存在可超越简单覆盖率、长度/保留率、置信阈值和已有适配器的差异。此线索偏可靠性，除非有明确权限/禁止披露后果，不称已发现安全问题。

还需区分位置保留与信息保留：保留下来的深层KV已经上下文化，删除原证据位置不必然让模型失去全部信息；不能把按位置算的“缺证据”直接当内部语义真值。若只是在现有作者限制上换数据/删词，不进入训练或新的模型矩阵。

新增近邻：[ContrastKV，ACL2026](https://aclanthology.org/2026.acl-long.417/)已做多query泛化的信号融合；[CachePrune，ACL2026](https://aclanthology.org/2026.acl-long.70/)通过编辑神经元/特征防注入，它不是本项目的物理token位置删除，不能据同名“剪枝”混报预算。动态规则撤销与历史效应仍受Forgetting Without Restarting、FlowKV、Request Order Matters等近邻限制。检索未命中不意味着空白。
