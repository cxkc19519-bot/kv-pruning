## 修正测量方式，不改写旧失败

对小型自建权限任务要求高Full可靠性，是避免把原本不会的题误说成压缩损坏的工程筛查。原AccessDenied与合成任务的门槛和停止决定继续有效，所有失败gate仍为false，不能用于旧screen。

对另立的标准、较难指令集合，不要求模型必须先做到近乎全对才能进行描述性测量。正确做法是先固定样本总体，保留Full和所有计划方法的结果，再分别报告：

| Full / 压缩 | 记录意义 |
| --- | --- |
| 对 / 对 | 保持成功（C→C） |
| 对 / 错 | 在该固定对照中的压缩新增错误（C→W） |
| 错 / 对 | 改善（W→C），不能隐去 |
| 错 / 错 | 既有失败，不冒充压缩新损坏 |

同时报告全样本分数、Full正确分母与C→W条件率；不要只展示C→W案例或某方法选出的失败子集来比较另一方法。这个做法是测量规范，本身已有近邻，不作为创新。新标准任务的支持量门槛不回填旧run，也不将Full正确子集称为独立确认集。

数据构造先于任何模型输出；检查器需按原源码运行，先用人工可判断的正负/边界样例验证、记录依赖与外部资源、核查缺失kwargs是否触发随机补值。不能盲目执行上游requirements或import训练/下载代码。本轮只做4个Python源文件AST与接口静态检查，尚未执行官方检查器。

IFEval只检查列出的可验证约束，不保证回答事实正确、任务内容完成或安全。没有配套事实/正常能力对照之前，校准分数不能支持安全特异性结论。

随后先做32 Full。若全对提示少于16、或截断超过3条，只报告该校准设置能力/预算不足并停止，不挑正确16条继续、不换提示/模型。不满足的压缩格明确标`not_run_support_gate`，不得填成失败。若支持量足够，压缩条件仍覆盖原32条全部提示，包括Full错题。每指令家族Full支持少于8时只列个数，不给稳定家族排名；这些数是小校准的描述性最低支持量，不是统计功效或显著性保证。

先CPU预检、固定数据/ID/判分器与新前端实现，再生成独立执行配置；不能直接把旧任务的失败gate或旧case套进此方案。以上阈值只服务新校准，不降低旧权限任务的95%标准。
